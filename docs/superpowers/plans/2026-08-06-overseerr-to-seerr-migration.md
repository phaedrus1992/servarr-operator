# Overseerr → Seerr Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this
> plan task-by-task. **`superpowers:subagent-driven-development` is overridden for this run per
> user global config (hides work inside subagent transcripts) — do not use it even though it's the
> skill's normal default recommendation.** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the operator's Overseerr integration to Seerr (its actively maintained successor)
across the API client, CRD types, image defaults, controller logic, charts, and docs — while
existing `ServarrApp`/`MediaStack` CRs spelled `app: Overseerr` keep reconciling.

**Architecture:** Mechanical rename of Rust types/fields/functions from `Overseerr*` to `Seerr*`,
with a serde alias on the two wire-visible spots (`AppType` enum value, `seerrSync` field) so
already-persisted CRs keep deserializing. The `overseerr` crates.io dependency is kept as-is (Seerr's
REST API is verified backward-compatible — see spec §1); only our wrapper module is renamed.

**Tech Stack:** Rust (kube-rs, schemars, serde), Helm charts, bash (`scripts/generate-crds.sh`).

## Global Constraints

- CI runs Rust 1.94.0 — run `cargo clippy --all-targets --all-features -- -D warnings` locally
  before pushing (project CLAUDE.md).
- Never hand-edit `charts/servarr-crds/templates/*.yaml` — it's generated by
  `scripts/generate-crds.sh`; always regenerate after a schema-affecting Rust change.
- The finalizer string literal `servarr.dev/overseerr-sync` must **not** change value — only the
  Rust constant name renames. Changing the value would strand the finalizer on any CR that already
  has it attached (nothing would ever match it to remove it, blocking deletion — see Task 4).
- `overseerr::apis::Error<T>` / `overseerr::models::*` in `servarr-api/src/servarr_v3.rs` refer to
  the **crates.io `overseerr` crate** (kept as a dependency, unrenamed) — do not touch these while
  renaming our own `OverseerrClient` wrapper type.
- Run `cargo fmt` after every Rust file edit, before staging (project rust.md convention).
